# Security policy

## Reporting a vulnerability

Report a security issue through GitHub private vulnerability reporting. Open a
draft security advisory on this repository (Security → Advisories → Report a
vulnerability). The form is documented in
[Privately reporting a security vulnerability](https://docs.github.com/en/code-security/security-advisories/guidance-on-reporting-and-writing-information-about-vulnerabilities/privately-reporting-a-security-vulnerability).

Do not open a public issue for a report in this scope. There is no security
email address.

## Scope

In scope:

- The scripts in `scripts/` and the workflows in `.github/workflows/`.
- A repository listed in this catalogue that is malicious or compromised.
  Include the `owner/name` and why you believe it is malicious or compromised.

Out of scope:

- Vulnerabilities in the upstream projects this list links to. Report those to
  the project that maintains the code.
- Scoring disagreements and ordinary listing requests. Open a pull request or a
  public issue for those.
